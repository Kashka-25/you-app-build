# YOU — Your Own Universe (web app)

A calm personal-growth "living biography" app: YOUrnal, PursYOUts (habits,
goals, dreams, ideas), YOUrney (memories, chapters, seasons), YOU (values and
Pillars), with optional Extras. React 18 + Vite + Tailwind, Supabase for
auth, data, storage and Edge Functions, the Claude API for AI reflections.

Live: https://yourownuniverse.life · Staging: https://staging--you-app-build.netlify.app

## Run it

```
npm install
cp .env.example .env   # or copy .env from Cassidy: VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY
npm run dev            # http://localhost:5173
npm test               # vitest
npm run build
```

Without `.env` the app stays on the loading screen (the Supabase client
throws on import). `DEV_MODE` in `src/lib/AuthContext.jsx` must stay `"live"`.

## Where things live

```
src/App.jsx              pre-auth gates, then routes (core screens eager, the rest lazy)
src/lib/AppDataContext   nearly every read/write and the XP rules (lib/xp.js)
src/lib/AuthContext      session and per-account prefs (auth user_metadata)
src/lib/plugins.js       Extras (all off by default) · lib/navigation.js menu + bottom bar
src/lib/offline.js       IndexedDB read cache + write queue (works with no signal)
src/components/          screens/, home/, journal/, pursue/, journey/, values/, sow/, ui/ …
../supabase/migrations   SQL, applied by hand in the SQL editor (never `supabase db push`)
../supabase/functions    Edge Functions (AI, Kronk, feedback, delete-account)
../supabase/schema       baseline.sql: the live schema, regenerated by snapshot.mjs
../supabase/backup       backup.mjs / restore.mjs (see below)
```

## Workflow

Feature branch → PR into `staging` → test on the staging site → PR
`staging` → `main`. Staging uses the **live** database, so migrations and
function deploys reach real users: back up first.

## Backups (Free plan, no Docker)

```
node ../supabase/backup/backup.mjs            # → ~/YOU-backups/<date>/
node ../supabase/schema/snapshot.mjs          # after any migration; commit baseline.sql
```

A backup holds every table, accounts (without password hashes) and every
stored file. It's private writing: keep it out of git and somewhere safe.
`restore.mjs <backup> --db-url <url>` rebuilds a fresh project (never the live one).
